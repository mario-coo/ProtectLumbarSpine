# 未来复查对比与自动化脚本使用说明

> **定位**：本仓库不仅是一份静态健康档案，更是一套**腰椎状态长期跟踪与复查量化比对工具库**。
> 未来当您再次进行腰椎 CT 或 MRI 复查时，可直接运行内置的 Python 自动化流水线，将新旧影像进行 1:1 精确解剖对照。

---

## 一、 环境快速配置

本工具库依赖标准的医学影像与科学计算 Python 栈：

```bash
# 1. 建议在 scripts 目录下创建独立的虚拟环境
cd scripts
python -m venv .venv

# 2. 激活虚拟环境 (Windows PowerShell)
.\.venv\Scripts\Activate.ps1

# 3. 安装依赖库
pip install -r requirements.txt
```

---

## 二、 自动化复查分析流程

当您从医院获取新的检查数据包（无论是医院光盘拷贝还是云胶片下载的 `.zip` 压缩包）：

### 步骤 1：解压 DICOM 文件
将新的 DICOM 切片文件夹解压至任意目录（例如 `D:\MedicalData\2027_FollowUp_CT`）。

### 步骤 2：运行自动化重组脚本
在终端中执行：

```bash
python scripts/dicom_pipeline.py "D:\MedicalData\2027_FollowUp_CT"
```

### 步骤 3：查看产出结果
脚本会自动完成以下操作：
1. **自动识别主薄层序列**（优先筛选 0.625mm 或 1.0mm 容积数据）；
2. **三维空间坐标重排**（严格按 PatientPosition 与 ImagePositionPatient 空间排序）；
3. **输出多平面重建成果**到 `output_analysis/` 目录：
   * `reconstructed_sagittal_soft.png`：新生成的正中矢状位全景软组织窗切面；
   * `reconstructed_sagittal_bone.png`：新生成的正中矢状位全景骨窗切面；
   * `axial_overview/`：全腰椎各节段横截面切片概览。

## 三、 新旧状态复查对比核心核对点（Before & After）

每次复查后，重点对照 `media/images/` 下保存的 **2026-04-06 原始基线图**：

| 评估观察指标 | 2026-04-06 原始基线状态 | 未来复查目标与好转信号 | 恶化预警信号 |
| :--- | :---: | :--- | :--- |
| **突出向后深度** | **5.6 mm** | 缩小至 4.0mm 以下（部分髓核脱水吸收萎缩） | 突出增大至 7.0mm 以上，或髓核游离脱落 |
| **硬脊膜囊有效前后径** | **14.8 mm** | 扩大至 16~18mm 以上（压迫缓解，容积恢复） | 缩小至 12mm 以下（椎管重度狭窄） |
| **右侧 S1 神经根间隙** | **被软组织包裹卡压** | 周围重新出现黑灰色的低密度脂肪衬托环 | 神经根明显肿大、与硬膜囊界限粘连不清 |
| **L4/L5 邻近节段** | **平整饱满无突出** | 依然健康，无继发代偿性退变 | L4/L5 也开始出现局限性膨出或突出 |

## 四、 仓库 Git 维护与同步建议

1. **不要将原始 `.dcm` 格式大文件提交到 GitHub**：
   * 原始 DICOM 体积往往超过 200MB~1GB，且包含个人就医敏感明文元数据；
   * 根目录已配置 `.gitignore`，会自动拦截所有 `.dcm` 和 `.zip` 提交。
2. **每次复查只需提交生成的对比分析图片与 Markdown 笔记**：
   * 将重组后的关键分析图放入 `media/images/`，并撰写新的跟踪日志（如 `docs/05_2027年复查比对日志.md`）；
   * `git commit` 并 `git push` 到您的独立健康仓库，形成终身数字健康脊柱履历。
